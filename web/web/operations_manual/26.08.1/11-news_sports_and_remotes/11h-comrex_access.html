11.H. Comrex Access

The Comrex Access permits high-quality audio connections to be made over the public internet. The Access Rack is the device that sits in the studio. The Access NX Portable is the device that goes to the remote site.

When everything is working correctly, the only action that needs to be taken in the studio is to route the device to the appropriate phone interface in a studio.

11.H.1. Troubleshooting the Comrex Access (From the Studio End)

Occasionally, problems will manifest that require the board-operator in the studio to assist with troubleshooting the Comrex Access.

Remember that there can always be multiple problems and you need to tackle the problems one by one. Do not panic just because the problem was not fixed on the first attempt. Stay calm and work the problem.

The user interface for Comrex Access Rack in Studio A is atop the telecom rack in the back of Studio A, next to the door. It has a monitor, keyboard, and mouse.

11.H.1.a. They Can’t Connect! (Checking the Network at the Studio End)

If the remote crew is having trouble making a connection, the first thing to check is whether the Access Rack can talk to the internet.

  1. Click on "Remotes" | "Manage Connections" to bring up the remote connections screen on the Access Rack.

  2. Check the top of the screen. Just below the menu bar is the Switchboard status bar. If everything is online, the status bar should say "Switchboard Online (Full Cone NAT)" or "Switchboard Online (Open)".

    "Switchboard" is a helper server, operated by Comrex, that helps Comrex devices connect to each other. WMUL‑FM does not need it to make a connection, but it helps with troubleshooting. Both Accesses have to be able to see the Switchboard. If one of them cannot see the Switchboard, then that one does not have internet access, which means that the two units cannot talk to each other.

    1. If the Switchboard status says "Switchboard Online (Full Cone NAT)" or "Switchboard Online (Open)", then the Access Rack has good internet connection. Continue at Step 3.

    2. If the Switchboard status says "Switchboard Online" but anything other than "(Full Cone NAT)" or "(Open)", then the Access Rack is connected to Marshall IT’s network, but there is a problem elsewhere that is preventing a full internetconnection. Off campus connections probably will not work, but on-campus ones might work.

    3. If the Switchboard status says "Switchboard Offline", then the Access Rack cannot talk to the internet.

    4. If there is a problem with the Switchboard, call the Operations Manager. A reboot may be able to fix the problem and that can only be done by the Operations Manager through the WebUI. If a problem with the Switchboard cannot be resolved, then the Access is not going to work today and the broadcast will need to switch to using the Opal, Linphone, or the Gentner.

  3. The main part of the screen is the list of remotes. There should be four or five items listed.

    • Loopback

    • Comrex Lab Voice

    • Comrex Lab Music

    • WMUL NX 1

    "WMUL NX 1" may be listed twice. One listing is the Access NX Portable talking through the Switchboard. If the remote crew has successfully connected, there will be a second entry for them because they connected directly, rather than through the Switchboard.

    1. If the Switchboard is online, but there are no entries for "WMUL NX 1", then that probably means that the Access Portable cannot talk to the internet and that the problem is on the remote end. Have the remote crew troubleshoot beginning with 11.H.2.a. We Can’t Connect! (Checking the Network at the Remote End)

    2. If the Access Rack is connected to any of the remotes, then it will say "Connected" just below the entry on the screen. If the Access Rack is connected to anything other than "WMUL NX 1", click the "Disconnect" button to free up the Access Rack for the Access Portable.

11.H.1.b. I can hear the remote crew, but they can’t hear me! (Audio Problems — Studio End)

Down at the bottom right of the screen are two pairs of level meters. The top set shows the levels going into the studio unit, and the bottom set shows the levels coming from the remote unit.

  1. If there are no levels on the top set of meters, then the problem is in the studio (most likely a routing error).

    1. Check that the source for "Access 1d" is set to "A Phn 1s" (or whichever studio and phone module you are using).

    2. Check the SuperPhone module in the audio console. Make certain that it is turned off and the appropriate caller module (Phone 1 or Phone 2) is in cue.

    3. Make certain that the "TB" knob is turned up. It should usually be at about "6", but try turning it up.

    4. Make certain that "MXM Source" is set to "AUD".

    5. Make certain that the Rivendell is in "PGM" and "AUD".

  2. If there are levels on the top set of meters, then the problem is at the remote end. Have the remote crew troubleshoot on their end using the instructions 11.H.2.c. The studio can hear me, but I can’t hear them! (Audio Problems — Remote End)

  3. If there are levels on the top set of meters, but the remote crew does not have any levels on their screen, then have the remote crew try disconnecting and reconnecting, and then try rebooting the Access Portable.

11.H.1.c. The remote crew can hear me, but I can’t hear them! (Audio Problems — Studio End)

Down at the bottom right of the screen are two pairs of level meters. The top set shows the levels going into the studio unit, and the bottom set shows the levels coming from the remote unit.

  1. If there are no levels on the bottom set of meters, then the problem is at the remote end. Have the remote crew troubleshoot on their end using the instructions 11.H.2.b. I can hear the studio, but they can’t hear me! (Audio Problems — Remote End)

  2. If there are no levels on the bottom set of meters, but the remote crew does have levels on their screen, then have the remote crew try disconnecting and reconnecting, and then try rebooting the Access Portable.

  3. If there are levels on the bottom set of meters, then the problem is in the studio (most likely a routing error).

    1. Check that the source for "A Phn 1d" (or whichever studio and phone module you are using) is set to "Acces 1s".

    2. Check the SuperPhone module in the audio console. Make certain that it is turned off and the appropriate caller module (Phone 1 or Phone 2) is in cue.

    3. Make certain that the "Cue" knob is turned up. It should usually be at about "5", but try turning it up higher.

    4. Make certain that the CR Microphones (CR Mic Front, CR Mic Middle, CR Mic Rear) are all turned off. (If any of the CR microphones are on, the speakers, including the cue speaker, will be muted.)

11.H.2. Troubleshooting the Comrex Access (From the Remote End)

Here are the steps for troubleshooting the Comrex Access from the remote side.

Remember that there can always be multiple problems and you need to tackle the problems one by one. Do not panic just because the problem was not fixed on the first attempt. Stay calm and work the problem.

11.H.2.a. We Can’t Connect! (Checking the Network at the Remote End)

If you cannot connect back to the studio, the first thing to check is whether you are actually connected to the internet. Just because you are plugged into a network jack or the JetPack, does not mean that you can access the internet. The surface streets might be open, but that does not mean the on-ramps to the interstate are.

  1. Press the "F2" button until you reach the "Remote Connections" page.

  2. The first place to check is the Switchboard indicator on the right side, under the "Disconnect" button. If you are connected to the on-campus wired network, it should say "Online (Symmetric NAT)". If you are connected to the JetPack, it should say "Online (Port Restricted NAT)".

    "Switchboard" is a helper server, operated by Comrex, that helps Comrex devices connect to each other. WMUL‑FM does not need it to make a connection, but it helps with troubleshooting. Both Accesses have to be able to see the Switchboard. If one of them cannot see the Switchboard, then that one does not have internet access, which means that the two units cannot talk to each other.

    1. If it says "Online (Symmetric NAT)" or "Online (Port Restricted NAT)", then the Access Portable has good internet, continue at Step 6.

    2. If it says "Switchboard: Online (Unknown)", then the Access Portable is still connecting and you need to let it keep working for a moment.

    3. If it says "Switchboard: Offline", then the Access Portable cannot talk to the internet.

  3. The second place to check is at the bottom of the screen. There should be a button that says "OnBoard" and, if you are using the JetPack, a button that says "JetPack".

  4. On Campus: Tap the button at the bottom of the screen that says "OnBoard". That brings up a window that will show you the status of the on-board ethernet connection.

    1. You are looking to see if the Access Portable has an IP address. It will be four numbers separated by dots. E.G. "192.168.1.2" . Sometimes it will display a long string of letters and numbers: that is not an IP address.

    2. If you have an IP address, but the Switchboard still says disconnected, then the problem is with the network. It is not letting the Access Portable see the internet. Give it a minute, then try rebooting the Access Portable. If that does not work, find a network technician.

    3. If you do not have an IP address, then check the network port on the back. There are two LEDs on the bottom of the jack. Those will light up and blink amber and green when there’s a network connection.

    4. If both of those LEDs are dark, the next thing to check is the cable and the jack.

      1. Make certain the cable is plugged in completely on both ends.

      2. Try a different cable.

      3. If another jack is available, try it.

      4. If none of that works, the next thing is to find a network technician and talk to them, or switch to the JetPack.

  5. JetPack: Tap the button at the bottom of the screen that says "JetPack". That brings up a window that will show you the status of the network connection to the JetPack.

    1. You are looking to see if the Access Portable has an IP address. It will be four numbers separated by dots. E.G. "192.168.1.2" . Sometimes it will display a long string of letters and numbers: that is not an IP address.

    2. If you have an IP address, but the Switchboard still says disconnected, then the problem is with the network. It is not letting the Access Portable see the internet. Give it a minute, then try rebooting the Access Portable. If that does not work, try rebooting the JetPack.

    3. If you still do not have a Switchboard connection, then the Access Portable is not going to work today. You will have to Switch to the Comrex Opal, Linphone, or Gentner.

  6. The next thing to check is the list of remotes. There should be five or six listed.

    • Loopback

    • Comrex Lab Voice

    • Comrex Lab Music

    • Access-1 On Campus

    • Access-1 Off Campus

    • WMUL-ACCESS-1

    The final entry, "WMUL-ACCESS-1", is the Access in the studio talking through the Switchboard server. It will only appear when both devices can talk to the Switchboard.

  7. If the Switchboard is working on the Access Portable, but "WMUL-ACCESS-1" is not in the list of remotes, then the problem is on the studio end. Have the board-operator begin troubleshooting at 11.H.1.a. They Can’t Connect! (Checking the Network at the Studio End) on Page 125 in Volume II

11.H.2.b. I can hear the studio, but they can’t hear me! (Audio Problems — Remote End)

  1. At the bottom of the screen are two pairs of level meters. Press "F2" until you reach the "Control Dashboard" page. In the middle of this page is larger set of level meters.

    On both pairs of meters, the top meter is for the local audio or the input buss. Which is to say, all of the microphones and other inputs plugged directly into the Access Portable. The bottom meter is for the remote audio or output buss. That’s all of the audio coming from the studio.

  2. If there are no levels on the input buss, then the problem is on this end.

    1. Make certain you are on the "Control Dashboard" page. (If you are not, press "F2" until you are.)

    2. Along the bottom of the page are a set of "Mute" buttons for each input. Along the left side of those buttons are little individual level meters for each input. The top of each input knob should also flicker green, yellow, and red.

      1. Make certain that the input that you are using is un-muted. The "Mute" button will blink faintly when muted to alert you to the fact that you are muted.

      2. Try turning up the input knob.

      3. Press "F2" until the "Audio Input Settings" page appears. Along the top of this page are the Mic / Line settings. For all the headsets, these need to be in "Mic Lo". If you are hooking up another mixer or something such as a laptop, those inputs would be in "Line". WMUL‑FM never uses the "Mic Hi" settings for anything. WMUL‑FM also never uses Phantom Power.

      4. If all of those settings are correct, but there are still no levels on next to the "Mute" button on on the input knob, then next thing to try is a different mic input or a different headset. The input or the headset may be bad.

    3. Once you have levels on the input knob, the next thing to check is the "Program / Producer" setting.

      1. Make certain you are on the "Audio Input Settings" page. If you are not, press "F2" until you are.

      2. At the bottom of each channel are two buttons: "Program" and "Producer". If you want a microphone to go back to the station, it must be in "Program".

        "Program" is the signal that goes back to the station. "Producer" is only heard in the headphones. The sports staff uses "Producer" during Football. Dr. Bailey and the spotter are only in "Producer" so that they can feed information to the Play-by-Play announcer without going over the air. The Play-by-Play and Color announcers are in "Program" so that their voices do go back to the station.

  3. If there are audio levels here, then the problem is on the studio end. Have the board-operator troubleshoot beginning at 11.H.1.c. The remote crew can hear me, but I can’t hear them! (Audio Problems — Studio End)

  4. If there are audio levels here, but not at the studio end, then the remote crew should try disconnecting and reconnecting, then try rebooting the Access Portable.

11.H.2.c. The studio can hear me, but I can’t hear them! (Audio Problems — Remote End)

  1. At the bottom of the screen are two pairs of level meters. Press "F2" until you reach the "Control Dashboard" page. In the middle of this page is larger set of level meters.

    On both pairs of meters, the top meter is for the local audio or the input buss. Which is to say, all of the microphones and other inputs plugged directly into the Access Portable. The bottom meter is for the remote audio or output buss. That’s all of the audio coming from the studio.

  2. If there are no levels on the output buss, then the studio is not sending you any audio and the problem is in the studio. Have the board-operator troubleshoot beginning with 11.H.1.b. I can hear the remote crew, but they can’t hear me! (Audio Problems — Studio End)

  3. If there are no levels on the output buss, but the studio has levels on their screen, then have the remote crew try disconnecting and reconnecting, and then try rebooting the Access Portable.

  4. If there are levels on the output buss, the next thing to check is the headphone control. Each headphone channel has two knobs that control the volume for the local and the return audio. The local is the program audio: all of the microphones that are plugged into this unit and in program. The return is the audio coming back from the studio and, optionally, the producer audio.

  5. If there are levels on the output buss, and the headphone return knob is turned up, then the next step would be to try a different headphone jack. It’s possible that the headphone jack has failed.

  6. If the headset does not work in any of the headphone jacks, then try a different headset. It’s possible that the headphone part of the headset has failed.
